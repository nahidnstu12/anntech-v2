Two apps, one Laravel project

Public (everyone) — Blade + Tailwind, no login
  1. Visitor opens / — hero, about, services, showcase, contact on one page
  2. Clicks Products → /products (filter by category)
  3. Opens a product → /products/{slug} (specs, images, brochure link)
  4. Fills contact form → POST /contact → queued email to Enovak
    Phase 3+: same form also saves inquiry in database
Admin (staff only) — React SPA at /admin
  1. Login (Sanctum session, CSRF cookie)
  2. Dashboard — counts (new inquiries, etc.) + activity feed for super admin
  3. Phase 2: Users & roles (super admin creates custom roles + permissions)
  4. Phase 3: Contact inquiries — list, read, status, internal notes
  5. Phase 4: Invoice clients → build invoice → PDF → send email → mark paid
  6. Phase 5: Edit website content (products, services, showcase, logos)

Landing page order: Hero → About (story, MD, values) → Services (cards, no separate service pages) → Featured products teaser → Showcase (project types / achievements, not client logo wall yet) → Contact (form + address + map)
Easy to miss — intentional choices
  • No /about, /services/…, /portfolio — keeps IA simple
  • Showcase on site = capability/project history — different from invoice customers in admin (Phase 4)
  • Client logo wall = Phase 5 CMS, not Phase 1
  • CMS (client contract “easy updates”) comes after inquiries + invoices + staff access
  • Mail always queued — not synchronous send
  • No payment gateway, no customer login portal

Key flows (detail)

Contact inquiry (Phase 3)

Visitor submits form → validate → insert DB row + queue email to company address → redirect with thank-you flash. Staff opens admin → list/filter → open detail (marks read) → change status (new / in progress / closed / spam) → internal notes → each change logged in activity feed.

Invoice (Phase 4)

Create invoice client (company, contact, email) → create draft with line items (totals recalc on server) → preview PDF → Send assigns number ENV-2026-0001 (never reused), queues email with PDF → status Sent → manually Paid / Overdue / Cancelled. Activity log records send (who, which client email) and status changes.

Content today vs CMS (Phase 5)

Now: edit content.php or client returns content-for-client.txt → you paste into PHP → deploy. Phase 5: same Blade views, loader reads MySQL; admin CRUD for products, services, showcase, company block, client logos, uploads; optional import from existing PHP once.
